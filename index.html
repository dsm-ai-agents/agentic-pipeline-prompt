The 5-Line Agentic Pipeline Prompt

One repeatable structure to turn any workflow into a team of Claude agents. You define the goal, Claude writes the plan, you approve, then it scaffolds the project in your folder. Nothing runs until you say so.

The framework

Five lines, always in this order. Each line answers one question Claude would otherwise guess.

Goal→ CLAUDE.md→ Agents→ Approval gate→ Local folder, no execution

1

Goal: input → output

Name the workflow in one sentence. A good goal has a clear input (raw regional data, 25 Markdown docs, a Supabase table) and a clear output (executive dashboard, organized knowledge base).

Create a [workflow name] that turns [INPUT] into [OUTPUT].

Why: if Claude can't name the input and output, it can't plan the steps in between.

2

Create CLAUDE.md first

Ask for the project's brain file before any agent exists: goal, workflow, folders, inputs, outputs, global rules, agent roles.

First create CLAUDE.md with project goal, workflow, folders, inputs, outputs, and agent roles.

Why: every agent reads it on start, so the whole team shares one plan. See the explainer below.

3

Agents: one file, one job, one line

List each agent as a numbered file with a single-line responsibility. Order = execution order. Each agent's output becomes the next agent's input.

agent_1_[verb].md : [one-line job] agent_2_[verb].md : [one-line job] agent_3_[verb].md : [one-line job]

Why: one job per agent makes failures easy to find and agents easy to swap or rerun.

4

Approval gate: propose before building

Make Claude show the architecture, workflow, folder scaffolding and outputs, then stop and wait for your yes.

Before creating files, show the proposed architecture, workflow, folders, and outputs for approval.

Why: fixing a plan costs one message. Fixing 6 generated files costs an hour.

5

Local folder, build only

Say where to build and that agents are created, not run. You activate them one by one later.

Do it in the local folder. Do not execute the agents. Only create them.

Why: you keep control. You review each agent file before it touches real data.

+

Rules optional

Add guardrails when the data is sensitive or tricky: read-only access, date formats, join keys, privacy, "never change body text".

Important rules: * Use read-only queries. * Never expose customer names, emails, or phone numbers.

Why: rules here get copied into CLAUDE.md, so every agent obeys them.

What is CLAUDE.md?

The project's operating manual. Claude reads it automatically every time it works in that folder.

Think of it as the briefing document you give a new team before a project. The agents are specialists. CLAUDE.md is the brief they all read on day one, so nobody works off a different version of the plan.

What goes inside

  • Project goalThe input → output sentence from line 1.
  • WorkflowAgent order and handoffs: who passes what to whom.
  • FoldersWhere raw input, working files and final outputs live.
  • InputsSource files, tables, connectors.
  • OutputsEvery deliverable with its file name.
  • Global rulesGuardrails every agent must follow.
  • Agent rolesOne line per agent, pointing to its .md file.

Why it matters

  • MemoryClaude forgets between sessions. CLAUDE.md doesn't.
  • ConsistencyAgent 4 follows the same rules as Agent 1.
  • HandoffsAgents share results through files, not chat.
  • ReuseCopy the folder, swap the data, rerun the pipeline.

Example skeleton

# Executive Reporting Pipeline

## Goal
Turn raw regional sales data into a one-slide executive PowerPoint
and an HTML KPI dashboard for regional managers.

## Workflow
agent_1_data_clean → agent_2_summary → agent_3_powerpoint
                                      ↘ agent_4_html

## Folders
data/raw/        # original files, never edited
data/clean/      # merged_data.csv from Agent 1
analysis/        # summary.md + kpis.json from Agent 2
outputs/         # executive.pptx, dashboard.html
agents/          # one .md per agent

## Global rules
- Agents share results through files, not chat.
- Never overwrite data/raw/.
- Stop and escalate if validation fails.

## Agent roles
1. Clean, join, validate, save merged data.
2. KPI, trend, exception and performance summary.
3. One-slide executive PowerPoint.
4. HTML KPI dashboard for regional managers.

Common mistakes

What breaks a pipeline prompt, and the one-line fix.

Vague goal

"Analyze my data and make something useful."

Fix

Name the input and the output: "turn raw regional data into an executive dashboard."

One mega-agent

"agent.md: clean, analyze, chart, and report."

Fix

One job per agent. If you write "and" three times, split it.

No approval gate

Claude builds 8 files on a plan you never saw.

Fix

"Before creating files, show the proposed architecture for approval."

Agents run immediately

Real data gets touched before you review anything.

Fix

"Do not execute the agents. Only create them."

Chat handoffs

Agent 3 can't find what Agent 2 "said".

Fix

"Agents share results through files, not chat."

Rules in your head

Date formats, join keys, privacy limits never written down.

Fix

Add a Rules block. It flows into CLAUDE.md for every agent.
